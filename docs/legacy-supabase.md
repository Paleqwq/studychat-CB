# StudyChat · 研究对话

参考 LibreChat 实际组件源码重做的黑白灰研究对话网站；**不是 LibreChat 分支，也不是原项目的 Vercel/Supabase 改造版**。源码参考范围、固定版本及 MIT 许可见 THIRD_PARTY_NOTICES.md。

- 被试入口：/。学号登记、自动固定分组、文本聊天、流式回复、自动保存、刷新恢复。不显示组别，没有模型选择、上传、工具或后台入口。
- 管理入口：/admin。Supabase 管理员登录、2×2 实验配置、两套模型连接、基础/人格提示词、可选 Bloom 基础提示词预设、三题两轮问答模式、分组人数、学号/组别筛选、会话查看、JSON 导出和单会话永久删除。
- 部署：Next.js App Router + Vercel Node.js Functions。
- 持久化：Supabase Auth + PostgreSQL；不依赖 Vercel 本地磁盘或进程内存。
- 支持 **OpenAI Chat Completions、OpenAI Responses、Anthropic Messages** 三套独立协议。

## 黑白界面

- 被试端采用 LibreChat 风格的 52px 窄图标栏、可收起会话栏、简洁顶栏和 24px 大圆角输入框。
- 欢迎页居中；开始交流后输入框固定在页面底部，用户消息为浅灰气泡，助手回复保持白底。
- 手机端改用可关闭的会话抽屉；使用说明和后台会话详情使用原生对话框，支持 Escape 和焦点约束。
- 后台、登录页、未配置提示、按钮、错误状态和站点图标全部使用中性灰度；没有彩色装饰或主题切换。
- 管理后台仍独立于被试页面，被试端不提供进入后台的链接。

## 三题两轮问答与 Bloom 基础提示词预设

学生端固定文案采用中性表述：进度仅显示「第一轮 / 第二轮 · 第 n / 3 题」，不介绍引导、独立作答、实验分组或 Bloom 层级；登记、帮助、轮次切换和常见错误提示同样中性化，仍说明学号关联记录、对话保存及隐私提醒。旧版自带标题/助手名称/告知和已保存的自动首题、切轮、结束消息在展示时兼容转换，不修改数据库历史或管理员导出；**此项文案更新不需要新增 SQL 迁移**。自定义标题、欢迎语、告知、题干和实际作答不做词语过滤，请管理员自行核对自定义内容。模型新增不主动介绍流程设计的输出约束，但不会要求模型在被直接询问时否认事实，亦不保证绝无提示泄露。中性界面不能替代招募阶段的数据用途告知和知情同意。

这是「程序编排 + 提示词引导」：程序管理题目和两轮进度，模型根据基础提示词引导并判定目标 Bloom 能力。**不自动覆盖已经部署的引导提示词或人格提示词，不自动开放模式。**

1. 已执行 001–003 的数据库，只执行 `supabase/migrations/004_question_mode.sql`，再部署新版代码。004 新增私有进度、判定记录及事务函数，保留旧会话、旧配置和旧提示词；可安全重跑。不要为增加功能重跑初始化脚本。应用会在缺少 004 时拒绝开启模式并显示升级提示。
2. 在「AI 提示词 → 预设基础模型提示词」选择「Bloom 引导式学习」，先查看完整预设，再勾选替换确认、点击「应用 Bloom 预设到编辑区」。应用不是发布，可撤销本次替换，也可以保留自己的基础提示词。预设文件为 `prompts/Bloom引导式学习_基础提示词.txt`。
3. 在「题目问答」开启模式，配置三道题的标题、题干、教师参考要点和各自的目标 Bloom 层级。预填先前设计的三道睡眠题，默认目标为创造，可选择任一层级。以后更换这一组题目及其参考要点即可，无须修改流程代码或通用引导预设。
4. 点击「保存并发布」。四组共用相同题目与目标，仍按原规则独立组合人格提示词、分配模型。模式、题目、参考要点、目标和基础/人格提示词都冻结在登记配置中，发布新版本不改变已有学生的任务。
5. 新学生登记后，程序直接保存并显示第一题，不需要先发送“开始”，也不伪造学生消息。第一轮一次一题：学生回答后，模型按基础提示词自适应引导。已经表现出的低层能力不机械重做；模型给出达标判断和一段学生原话证据，服务端校验格式、目标层级及引文来源，提交成功后才发送下一题。
6. 第三题引导完成后，程序进入第二轮，按原顺序原样重发这三道题。每题接收一次非空作答后直接继续，即使作答为“我不知道”也记录；**不调用模型、不判断对错、不提供提示、纠错或点评**。仅显示中性接收确认及下一题，最终保存后关闭输入。

可靠性与边界：

- 数据库在同一事务里保存回复、判定和进度；刷新不重开，失败重试沿用原作答，不重复推进。版本检查拒绝旧浏览器窗口对已改变题目的提交；已完成轮次的重复请求只恢复结果。
- 新题在保存成功后才显示。第一轮先缓冲并验证模型 JSON，不向学生输出原始控制字段、判定证据或未提交的下一题。正常自由聊天的流式响应不变。
- 后台详情/JSON 导出包含冻结题目、当前进度，以及 `question_turns` 中每轮的前后状态和模型判定。第二轮的 `assessment` 为 null。该记录只是模型判定依据，不是隐藏思维链，也不是经验证的认知量表。
- 程序能保证顺序和持久化，**不能保证模型对知识或 Bloom 能力的判断永远正确**。正式研究前应对每个模型测试达标误判、长期卡住、越级引导及提示泄露，并由教师抽查真实作答。参考要点不要包含机密，模型仍可能被诱导复述。
- 任务相关历史按原有字符预算截取；当前题目、参考要点和目标每次重新注入。基本引导预设是所有条件共用的规则，人格只影响表达，不应改变判定门槛。
- 继承原有暂停、8次/分钟、200次/会话及租约限制，不靠强制跳题伪造达标；达到上限需联系研究人员。
- 演示模式只模拟流程：每题第一轮第一次返回固定追问，第二次模拟达标，并明确标注“不是真实 AI 评估”。不连接 Supabase、不调用提供商、不保存真实密钥。

## 2×2 实验设置

| 模型因素 | 有人格提示词 | 无人格提示词 |
| --- | --- | --- |
| DeepSeek | 共用基础提示词 + 额外人格提示词 | 仅共用基础提示词 |
| ChatGPT | 共用基础提示词 + 额外人格提示词 | 仅共用基础提示词 |

1. 在「模型连接」分别切换 DeepSeek / ChatGPT，填写各自的协议、API 地址、密钥、真实模型 ID 和生成参数。每套连接供该模型的两个组共用，避免同模型的两个条件意外使用不同参数。
2. 在「AI 提示词」填写四组共用的任务/规则，以及仅有人格组使用的额外人格材料。**不自动生成正式实验人格**，人格材料不能为空。两种模型共用同一份人格文本；「无人格」意为不额外注入人格，不代表模型本身没有语言风格。
3. 四组的页面标题、助手名称、欢迎语、告知文案相同；不要在公共文案中透露模型或条件。
4. 使用下拉框预览各组最终系统提示词，点击「保存并发布」原子生成四组配置。两套连接和提示词必须同时完整，不会在配置缺失或某模型请求失败时自动换组/换模型。
5. 被试输入完整学号后，服务端在**当前登记人数最少的组中随机选择一组**。数据库行锁把分配、发布与管理员删除串行化；人数按所有版本中仍保留的登记累计。在无删除的新增过程中四组登记数最多相差 1；删除可能暂时打破均衡，后续登记优先补人数较少的组。该机制不是按学号尾号分组，也不保证完成实验的人数均衡。
6. 同学号、同身份的重复请求恢复同一会话，不能换学号或重抽；不同身份不能凭已登记学号读取原对话。已登记会话冻结当时的模型 ID、提示词、实验版本及生成参数；已分组会话的连接信息随对应模型的最新发布更新，规则见下文。新登记使用完整的新配置。
7. 「对话记录」可按完整学号或组别查询；单会话 JSON 包含 `student_id`、`group_code`、`model_factor`、`personality`、`assigned_at`、`experiment_revision`、实际提示词/模型和全部消息，不包含密钥。

重要边界：学号保存为字符串，前导 0 不丢失，首尾空格去除，字母统一大写；允许 1–32 位数字、字母、下划线、短横线。**学号不是密码，也不验证真实学生身份**；目前不包含学校 SSO、名单校验、跨设备恢复或管理员重绑入口。若研究需要防冒名登记或共用实验室电脑，应先补充个人招募凭据/账号方案；不要让不同被试共用一个已登记浏览器身份。被试页面虽不提供组别信息，模型仍可能自述身份或复述提示，不能据此宣称完全盲法。入口勾选提示不替代正式知情同意流程。

## 已初始化数据库的升级步骤

1. 暂停招募并备份研究数据库；在 Supabase SQL Editor **完整运行一次** `supabase/migrations/002_factorial_experiment.sql`。不要重跑 001，不要删除旧表。
2. 升级会新增实验版本、四组配置映射和私有学号登记表；原有会话/消息保留为「历史 / 未分组」，不算作新实验样本。登记表不随 Auth 用户删除而级联删除；不可随意清理已登记的匿名 Auth 账号。
3. 随后部署/重启新版代码。002 会停用旧的会话创建和发布 RPC，所以旧服务器不应在升级后继续作为正式入口。
4. 确保管理员 Auth 账号已经加入 `admin_users`，后台匿名 Auth 身份创建已开启。学号是研究标识，Supabase Auth 会话令牌负责访问隔离；二者用途不同。
5. 登录后台填写两套连接和正式人格材料，再发布并开放。用测试学号在独立测试环境验证四组请求、记录隔离和流式回复后再招募；正式库登记会计入均衡人数，勿混入随意测试样本。

### 已登记会话更新连接

在「模型连接」选择 DeepSeek 或 ChatGPT，修改连接并点击「保存并发布」。已分组会话的**下一次请求**使用对应模型因素的最新 API 地址、地址方式、协议、认证方式/Workspace、输出上限参数名及密钥；不跨模型因素借用连接或密钥。未发布的编辑不生效。

- 原模型 ID、系统提示词、学号、分组、实验版本、Temperature、输出 Token 数和历史消息保持不变；不修改已有 `config_versions` 或会话绑定，也不删除任何记录。
- 新接口必须支持旧会话冻结的原模型 ID。修改后台模型 ID 只影响新登记，不会把旧会话换成新模型；如果新网关不支持旧 ID，旧会话仍会报模型错误。
- 每次请求读取一份不可变的已发布版本，正在生成的回复不会中途切换；发布后下一次新请求/失败重试使用最新连接。已完成轮次的重复请求只恢复已保存回复，不重新生成。
- 最新连接或密钥缺失、读取失败时不退回旧密钥，也不自动改用另一个模型；请修复并重新发布。域名允许列表、HTTPS、DNS/内网限制和密钥加密继续生效。
- 历史未分组会话无法确定模型因素，保留登记时的连接；不依据模型名字或当前选中的后台标签猜测。
- 「会话详情」分别显示登记配置和当前连接版本/最终地址。JSON 的 `config` 是原登记快照，`connection` 是读取详情时的当前连接说明，均不含密钥；**不是历史每条请求的连接审计**。如需追溯连接变更，可结合已有发布版本，但本功能不新增逐轮连接日志。
- 此功能只需部署新版代码，**无需额外 SQL**。演示模式仅模拟连接说明，不保存或调用真实密钥。

启用管理员删除功能：如果 002 已执行，只需在 SQL Editor 完整运行 `supabase/migrations/003_admin_delete_conversation.sql`，然后部署新版代码。003 只安装函数和权限，不会主动删除任何数据，可安全重跑；不要为新增此功能重跑 001、002 或 `new_project_init.sql`。

### 管理员删除会话

在「对话记录」列表或会话详情点击「删除」，核对学号/会话编号，再输入“删除”并确认。网站不提供批量删除或被试自行删除入口。

- 永久删除所选会话、全部消息、请求记录及对应学号登记，网站内无法撤销。建议先在详情导出 JSON 备份；导出不包含密钥，也不等于可直接导入的数据库备份。
- 释放学号和原浏览器身份，允许按当前实验版本重新登记/分组；对应分组人数减少。正式研究中的删除会改变样本与均衡计数，请按研究数据管理流程操作。
- 不删除 Supabase Auth 用户、管理员、其他会话、模型密钥或历史实验/配置版本。
- 正在生成回复的会话返回 409；等待完成后再删除。租约已过期的中断会话可删除，旧请求不能重新写入已删除会话。
- 后端校验登录、非匿名管理员白名单、同源请求和明确删除确认；数据库 RPC 仅允许服务端执行，并再次校验管理员身份，在一个事务中删除关联数据。
- 删除后刷新列表和分组人数；页尾最后一条删除后返回上一页。演示模式只清理本浏览器对应的演示会话和快照。

需要重新构建本地正式服务时运行 `npm run build`，再 `npm run start -- --hostname 127.0.0.1 --port 3001`。停止现有本地服务后再启动，避免端口冲突。Vercel 则重新部署同一项目，环境变量配置不变。

## 1. 创建并配置 Supabase

1. 创建 Supabase 项目；请根据研究的数据存储要求自行选择地区。
2. 新项目在 SQL Editor 按顺序完整执行 `supabase/migrations/001_studychat.sql`、`002_factorial_experiment.sql`、`003_admin_delete_conversation.sql`、`004_question_mode.sql`、`005_english_assistant.sql`、`006_english_groups.sql`、`007_english_curriculum_and_delete.sql`、`008_english_learning_pause.sql`，也可一次执行 `supabase/new_project_init.sql`（仅用于新空项目）。已有数据库按上文只执行尚未应用的升级。
3. 在 Authentication 设置中开启 **Anonymous Sign-Ins**。
4. 通过 Dashboard 手动创建管理员邮箱账号并设置强密码。本网站不提供公开邮箱注册页面；管理员资格由数据库白名单控制。不要为限制邮箱注册而误关匿名身份创建所需的总注册开关，正式采集前必须验证匿名登录能正常工作。
5. 在 Authentication → Users 找到管理员 UUID，用实际 UUID 执行：

~~~sql
insert into public.admin_users(user_id)
values ('在这里替换为真实管理员UUID');
~~~

此 UUID 必须属于已创建的非匿名 Auth 用户。仅登录成功不代表拥有后台权限；数据库白名单也必须包含该账号。禁止将被试匿名账号加入此表。

登录故障需要区分：Supabase 网络中断、超时或服务错误返回 503，不应显示为「会话过期」；真实无效的登录状态返回 401，非管理员返回 403。浏览器登录成功后，如果网站服务端暂时无法校验身份，登录页可点击「重试连接（使用已有登录）」，不会重新输入密码、退出账号或清除研究身份。此按钮仍须通过服务端身份与管理员白名单验证，不能绕过权限。若出现网络错误，请分别检查浏览器和运行 Next.js 的机器能否访问 Supabase；不要通过重建账号、删除数据库记录或关闭鉴权处理网络故障。

6. 公网研究建议开启 Supabase CAPTCHA（Cloudflare Turnstile），在 Supabase 配置对应 secret，在网站环境变量中填 NEXT_PUBLIC_TURNSTILE_SITE_KEY。按照 Supabase 官方说明设置注册/匿名登录的限流。
7. 研究限定人群可再设置 STUDY_ACCESS_CODE，通过研究邀请单独告知被试。它是共享访问码，**不是**被试身份、跨设备恢复凭据或完善的反滥用系统。

## 2. 环境变量

参见 .env.example。本地真实联调使用 .env.local，Vercel 在 Project Settings → Environment Variables 中设置。不要把密钥提交到 Git。

| 变量 | 用途 |
| --- | --- |
| NEXT_PUBLIC_SUPABASE_URL | Supabase 项目 URL |
| NEXT_PUBLIC_SUPABASE_PUBLISHABLE_KEY | 可公开的 publishable key（也可用兼容的旧 anon key） |
| SUPABASE_SECRET_KEY | 服务端 secret key（也可用旧 service_role key） |
| CONFIG_ENCRYPTION_KEY | 32 字节随机密钥的 Base64 编码，仅服务端使用 |
| AI_ALLOWED_HOSTS | 允许访问的 AI 主机名，逗号分隔，精确匹配 |
| STUDY_ACCESS_CODE | 可选研究访问码，不公开到前端包 |
| NEXT_PUBLIC_TURNSTILE_SITE_KEY | 可选 CAPTCHA 站点标识 |
| DEMO_MODE | 正式环境保持 false |

生成加密密钥：

~~~powershell
node -e "console.log(require('crypto').randomBytes(32).toString('base64'))"
~~~

妥善备份 CONFIG_ENCRYPTION_KEY。旧配置的 API 密钥依赖它解密；**不要直接更换或丢失**。研究中的每个会话绑定配置版本，也绑定当时的 API 凭据。轮换或撤销提供商密钥时，应规划已有会话的结束或单独迁移，不要期待更改后台配置自动更新老会话。

AI_ALLOWED_HOSTS 默认支持 api.openai.com、api.anthropic.com、api.deepseek.com、openrouter.ai、api.siliconflow.cn。自建或其他网关需要先加入其**可信的公共 DNS 主机名**并重新部署。仅允许 HTTPS/443，禁止重定向、账号密码 URL、查询参数和解析到内网/本机的地址。不要把不可信、可被任意修改 DNS 的域名加入允许列表。

## 3. 发布到 Vercel

1. 将本文件夹作为 Git 仓库根目录提交到你自己的仓库，导入 Vercel；也可以将本文件夹作为已有仓库的 Root Directory。
2. Framework Preset 选 Next.js，使用 Node.js 22 或更高版本。构建命令 npm run build，安装命令 npm ci。
3. 设置生产环境变量并部署。公开 NEXT_PUBLIC_ 变量会在构建时注入，更改后须重新部署。
4. 在 Supabase 配置生产站点 URL；需要验证码时，把生产域名加入 Turnstile 允许列表。
5. 登录 /admin，填写两套模型连接和基础/人格提示词，同时发布四组第一版配置。在此之前不接受新学号登记。
6. 用两个独立浏览器/无痕窗口完成下方验收，确认研究告知和数据管理流程，再分发参与链接。

聊天路由设置 maxDuration=180 秒，上游模型请求在 120 秒后中止，数据库租约 150 秒后可恢复。你的 Vercel 计划和网关也必须支持对应的函数时限与流式响应；实际平台上限可能更低。必要时调整 src/app/api/chat/route.ts 中时限和 SQL 租约，保持一致。长耗时的后台任务/异步智能体不在本项目范围。

## 4. 后台协议配置

DeepSeek 和 ChatGPT 两套连接分别保存协议、API 地址、地址方式、模型和密钥，不共用一个地址。每套连接可选择：

- **基础地址**：填写基础路径，例如 `https://api.example.com/v1`，按所选协议追加下表的路径。同协议的完整端点也可粘贴，不会重复拼接。
- **完整接口地址**：填写服务商给出的完整请求 URL，原路径（含末尾斜杠）会被保留，不删除或追加路径。适合不同协议使用独立前缀或非标准路径的网关；HTTPS、域名允许列表和内网限制仍然生效。

后台显示与服务端相同算法计算的「最终请求地址」。已知接口后缀与所选协议不一致时会阻止发布，不再静默替换路径。切换协议不会自动更换服务商、模型或密钥，请核对当前模型的地址和认证方式。

| 后台选择 | 自动追加路径 | 认证 / 提示词 / 输出上限 |
| --- | --- | --- |
| OpenAI Compatible | /chat/completions | Bearer；messages 中的 system；可选 max_tokens 或 max_completion_tokens |
| OpenAI Responses | /responses | Bearer；instructions + input；max_output_tokens；store=false |
| Anthropic | /messages | 默认 x-api-key，也可选 Bearer；anthropic-version: 2023-06-01；顶层 system；max_tokens |

Anthropic 还提供可选 Workspace ID 字段，供需要 anthropic-workspace-id 的服务使用。模型 ID 必须填写你的提供商实际支持的值，不自动更换模型；Temperature 留空时不发送此参数，兼容不支持温度参数的模型。

基础地址模式下，OpenAI / Anthropic 官方裸域名自动补齐 `/v1`；DeepSeek 的 Anthropic 兼容地址补齐 `/anthropic/v1`，完整请求路径为 `/anthropic/v1/messages`。仅对这些已知官方域名补齐，自定义网关不猜测前缀；完整接口模式完全以输入路径为准。旧配置未包含 `api_url_mode` 时继续按基础地址模式处理，无需新增 SQL 迁移。

API Key 以 AES-256-GCM 加密后保存在私有配置表中。后台读取只返回“已配置”状态；不回传原文或密文。更换 API 域名必须重新填写密钥，防止旧密钥被误发给新主机。

保存并发布连接变更会影响同模型因素的已分组旧会话，不需要删除会话或重新登记。只有地址、协议、认证和密钥等连接字段同步；模型 ID、提示词及生成参数仍使用原登记快照。后台模型 ID/生成参数的修改只影响新登记。

### New API 中转站

New API 站点按其对外接口选择现有协议；无需新增独立的“New API 协议”。例如使用 `https://ai.megumi.ovh/v1` 作为基础地址时，三种适配器分别请求 `/v1/chat/completions`、`/v1/responses` 或 `/v1/messages`，模型 ID 和令牌填写该站实际提供的值。自定义网关不会自动为只有域名的地址补齐 `/v1`，以免破坏其自定义路径。如果网关各协议不共用基础路径，分别在对应模型下选择「完整接口地址」并填写实际端点。

中转域名须逐个加入 `AI_ALLOWED_HOSTS`，修改后重启服务；部署到 Vercel 时须同步设置该项目的环境变量。允许列表不放开内网保护：若本机 DNS/代理把域名改写到私有地址，仍会被阻止，应先排查 DNS、代理/TUN 和分流规则，不要直接允许全部内网地址或关闭地址验证。

本地同源校验兼容 Next.js 将回环地址规范化为 `localhost` 的行为，但只根据相同端口的回环 `Host` 恢复浏览器实际使用的地址。不同主机、端口或协议的请求仍被拒绝，不使用调用方的 `X-Forwarded-Host`/`X-Forwarded-Proto` 扩大允许来源。

三种协议均为**纯文本对话适配**。不包含工具调用、图片/音频输入、文件上传、联网搜索、Claude Code/OAuth 登录、Azure 特殊部署路径、Gemini 原生协议。第三方网关仍需符合所选协议、接受 SSE 流式返回；本地模拟测试不能替代真实接口联调。

## 数据行为与研究边界

- 被试填写学号，后台通过 Supabase 匿名 Auth 获取独立访问身份。学号与身份固定绑定，同一浏览器刷新恢复同一会话；学号/组别关联不存储在公开会话列中。
- **跨设备/清除浏览器数据后不能凭学号或会话编号找回身份。** 研究中如需长期跨设备追踪，应另加受控个人招募凭据或账号体系。当前不包含自助或管理员重绑界面。
- 服务端从数据库读取历史和系统提示词，不接受客户端上传模型、提示词、API 地址或伪造历史。
- 每轮开始原子保存用户消息和待生成回复。回复过程中约每 2.5 秒或每 1000 字符检查点保存；完成落库后才显示“已保存”。
- 断线/关页/函数终止可能造成最后一个检查点后的部分文本未保存。不会将缺少完成信号的流静默记为完整回复；过期租约标记为失败，原会话可重试，重试不会复制用户消息。
- 每个会话每分钟最多 8 次模型生成尝试，累计最多 200 次。此限制不能阻止新匿名身份滥用，公网部署还需 CAPTCHA、Supabase/Vercel 限流和提供商费用限制。
- 长历史只发送最近约 60,000 字符（再加系统提示词），数据库保留完整历史。此为字符预算，不是精确 token 计数；小上下文模型需要调整。
- 新配置只影响**新会话**；已有会话使用原配置。暂停开关全局生效，但已经生成中的请求会正常结束。若老会话使用了错误模型或过低输出限制，应由研究者规划新会话，而不是在采集中静默改版本。
- 后台单会话 JSON 导出含消息时间、完整/失败状态、提示词与模型版本，不含 API 密钥。时间保存在数据库中为带时区时间；后台显示使用访问设备时区。
- 本项目不自动删除研究数据、不制定保存期限、不代替研究伦理审批或知情同意流程。请在招募前完成告知、授权、保留期限、删除/撤回及数据备份方案。
- 数据库启用 RLS：被试只能读取自己的安全会话列/消息，无客户端写入权限。学号分组表、实验版本、配置映射、配置 ID、租约令牌、管理员白名单与密钥不对客户端开放。后台通过服务端验证用户及白名单访问。
- 模型仍可能在对话中被诱导复述提示词，因此系统提示词**不应包含机密**。

## 独立英语助教

侧栏「新对话」下方的「英语助教」打开 `/english-assistant`。该模块针对三份 PEEC 教案、讲课稿和课件，固定采用六个 BOPPPS 阶段：导入 → 学习目标 → 前测 → 参与式学习 → 后测 → 总结，默认包含原有 12 项在线活动。PEEC 为 Point / Evidence / Explanation / Connection。前测用于诊断，回答「不会」也会继续；参与式练习和后测只有在学生作答满足当前要求时推进。默认阅读后测由原材料的 80–100 词作业改编，修改后需要重新提交完整正文与结构说明。

英语助教有独立的匿名浏览器身份、学号登记、分组人数、提示词版本、启停状态、消息、进度、重试租约及限流。英语仅设 **DeepSeek · 有人格** 与 **DeepSeek · 无人格** 两组，按英语累计登记人数最少随机分配，不登记到原 Bloom 四组，不读取原会话的题目或作答。两者可以分别登记同一学号；暂停和记录管理彼此独立。

独立后台为 `/admin/english-assistant`，提供课程启停、登记说明、**提示词配置**、**BOPPPS 流程配置**、英语两组人数及独立记录查询、详情、JSON 导出和删除。模型直接沿用原「模型连接」中的 DeepSeek，不额外配置或修改原模型，不要求 ChatGPT 可用，也不回退到 ChatGPT。新登记冻结当时的 DeepSeek 模型 ID、Temperature、输出预算、英语提示词和完整课程内容；后续请求与原分组会话一样使用最新发布的 DeepSeek 地址、协议、认证及密钥，具体规则见上文模型连接更新说明。

英语基础教学提示词为两组共用，人格提示词仅用于人格组。英语提示词第一次发布前默认参考原人格提示词，发布后独立保存；原 Bloom 基础提示词和题目问答配置不进入英语会话。六阶段顺序、PEEC 学习材料、证据校验与 JSON 输出规则由服务端和程序控制，基础提示词用于补充教学表达；具体教学活动在「BOPPPS 流程配置」编辑。新发布影响新登记；既有分组、提示词和课程快照及学习进度保持原样。

流程配置预填完整默认教案。每个阶段可修改说明（1–300 字），增删活动（每阶段 1–8 项，总共最多 24 项），编辑活动标题（1–120 字）、学生任务（1–4000 字）和达标条件（1–2000 字）。参与式学习和后测可设置英文正文词数范围（整数 1–1000，下限不大于上限）；词数检查按当前活动配置执行，不为其他任务套用默认阅读词数。恢复默认内容需确认且只修改草稿，保存并发布后对新登记生效。学生进度栏只收到阶段说明和活动标题，当前任务通过助手消息展示，内部判定条件仅管理员可查看。历史空课程快照继续原 12 项活动，不跟随最新发布课程。

学生明确表达「不想继续学习」「先休息一下」等停学意愿时，英语助教自动保存暂停状态并提示稍后继续；学生也可以使用聊天区的「暂停学习 / 继续学习」按钮。暂停期间保留当前题目、BOPPPS 阶段、活动进度、历史记录和登记时的课程/提示词/模型快照，刷新页面后仍可恢复，继续学习从同一活动接着作答。暂停或恢复不推进活动、不改变组别，也不调用模型或占用 AI 请求次数；控制请求有独立限流。仅表达「不会」「很难」等学习困难时仍继续辅导，不据此自动暂停。此功能仅影响该英语会话，原 Bloom 与管理员的课程启停保持独立；管理员关闭英语课程时，学生点击继续也不能提交新的教学请求。

英语记录列表和详情页提供「删除会话」。管理员输入目标学号确认，生成回复期间禁止删除。删除事务只清理目标英语会话及其消息、进度、判定回合和请求记录，008 新增的暂停/继续控制记录随目标会话级联删除，释放该英语身份与学号登记，并更新两组人数；重新登记会重新分组。系统保留最小删除审计（不保留正文），仍被其他英语会话或英语状态引用的配置不会清理。删除不触及 Bloom 会话、分组或模型连接，网站内无法撤销；如需保留正文，请先导出 JSON。
